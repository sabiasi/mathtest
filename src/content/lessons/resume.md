A **resume** (or CV) is a one-page summary of what you can do. Recruiters often spend under 30 seconds on the first look, so clarity wins.

## The structure

1. **Header**: name, email, city, and links to GitHub, your portfolio and LinkedIn.
2. **Skills**: languages and tools you've actually used (Python, Git, SQL, FastAPI…). Group them; don't rate yourself with stars or bars.
3. **Projects**: your best 2–4, each with a link and 2–3 bullet points. For a beginner, this is the most important section.
4. **Experience**: any jobs, even non-tech ones. Teamwork and responsibility count.
5. **Education**: degrees, bootcamps, courses like CS50.

## Writing strong bullet points

Start with an **action verb**, say **what you built** and **with what**, and add a **result** if you can:

❌ "Worked on a website"
✅ "Built a study-tracking web app with React and TypeScript, including 9 automated tests and offline storage"

Numbers make bullets stronger: users, speed, tests, size.

## Common mistakes

- More than one page (as a beginner).
- Listing technologies you've only watched a video about. Interviewers *will* ask.
- Typos. Read it aloud, and ask someone else to read it.
- One generic resume for every job. Adjust it to match each job description.

## Key takeaways

- One page: header, skills, **projects**, experience, education.
- Bullets = action verb + what you built + tools + result.
- Only list what you can talk about confidently.
